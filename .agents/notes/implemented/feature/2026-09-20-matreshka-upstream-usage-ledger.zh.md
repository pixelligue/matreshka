# Agent Note: Matreshka upstream usage ledger

Status: implemented

[English](2026-09-20-matreshka-upstream-usage-ledger.md) | 中文

## 问题

Harness 会话日志记录模型 token 数量，但无法按产品用户核对标题生成、失败的尝试、OpenRouter 咨询和服务商收费。账户余额混合了其他请求，token 数量也不等于实际扣费。

## 决策

产品 API 为通过聊天、咨询、工具选择或其 Web 搜索路由发出的每次已认证上游尝试写入一条 `usage_events` 记录。记录归属已认证用户，只保存操作元数据、状态、服务商报告的 token 数量、字节数、可选的服务商请求 ID 和可选的金额。聊天流在关闭时写入记录，包括中断的流；非流式路由在上游尝试后写入。API 提供按用户隔离的事件列表和分组汇总。

金额以指定货币的十亿分之一为整数保存。服务商报告的费用、按 OpenRouter 标价计算的估算费用和未知费用保持区分。缺少用量时不会记为零用量或零费用。上游尝试后的数据库写入采用尽力而为方式，记账失败不会替换模型或工具响应。

## 考虑过的替代方案

- **只从 Harness 会话日志重建费用。** 已拒绝：日志缺少标题请求的用量、服务商费用和部分失败尝试，也无法识别所有 OpenRouter 与搜索调用。
- **保存完整请求和响应正文。** 已拒绝：提示词、工具结果和凭据并非费用核算所需，保存它们会增加敏感数据的留存。
- **把当前公开价格当作实际扣费。** 已拒绝：折扣、试用额度、价格变更和服务商收费可能不同于费率计算；账本将费率计算标为估算。
- **将桌面端直接访问 Keenable 的流量改经 API。** 暂缓：这会改变现有 Web 传输，而其公共接口目前不报告费用。Harness 会话日志仍能显示这些工具调用。

## 后果

现有会话不会回填。聊天记录包含标题生成，但不会单独标识它。桌面端直接调用 Keenable 的搜索和抓取不进入 API 账本。服务商响应缺少用量或费用时，相应字段为空；上游尝试后数据库故障可能留下缺口，服务器只记录该故障而不改变上游结果。
